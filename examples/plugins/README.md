# 示例插件

三个可以装的示例，各自展示插件系统的一条主要路径。源码在仓库里，编出来的是可直接安装的 zip 包。

| 插件 | 用到的机制 |
|---|---|
| `comment-guard` 评论反垃圾 | 过滤器（`comment.judge`）、动作（`comment.created`）、设置分组、键值存储、资源记录、侧栏小组件、公开接口 |
| `visit-stats` 访问统计 | 前台脚本、公开接口、动作（文章发布 / 更新 / 回收站）、侧栏小组件 |
| `comment-notify` 新评论邮件通知 | 动作（`comment.created`）、宿主能力（发邮件）、站点地址 |

三个插件互相独立，可以只装一个。插件之间不能互相调用，所以示例里也没有互相依赖——
`spec.dependencies` 的用法见 [插件开发](../../docs/plugin-development.md#依赖别的插件)。

## 构建与安装

```bash
sh examples/plugins/build.sh              # 全部
sh examples/plugins/build.sh visit-stats  # 只编一个
```

产物是 `examples/plugins/<插件名>.zip`。到后台「插件 → 安装插件」上传，然后启用：
声明了能力的插件，启用时会把要用的能力逐条列出来，确认后才会加载。

装好之后：

- **评论反垃圾**：在「插件 → 评论反垃圾 → 反垃圾规则」里填关键词与链接上限。之后发一条带关键词的评论，
  它会被判为垃圾、不进审核队列，留言列表里能看到「拦截记录」。
- **访问统计**：发布一篇文章，用浏览器打开它（同一个会话里同一篇只计一次），再到主题设置里把侧栏
  加一个「热门文章」小组件（类型选「插件小组件」，再选 `visit-stats/popular`），就能看到排行。
- **新评论邮件通知**：在「插件 → 新评论邮件通知 → 通知」里填收件人。站点要配好 SMTP，
  否则邮件只会进队列然后失败，后台的日志里能看见原因。
